Demo 03 — §3.4. A linha que mais gera bug nesta aula

Duas páginas idênticas, com o mesmo CSS autoral (.card-title { color: #6f4e37; font-size: 2rem }). A única diferença é a ordem das duas linhas no <head>.

meu CSS antes do framework abrir sozinha 

<style> .card-title { … } </style>
<link href="…bootstrap.min.css" rel="stylesheet">

meu CSS depois do framework abrir sozinha 

<link href="…bootstrap.min.css" rel="stylesheet">
<style> .card-title { … } </style>
Roteiro no DevTools: abra a página da esquerda em uma aba, clique com o botão direito no título → Inspecionar → painel Styles. A declaração perdedora aparece riscada, e logo acima dela está a regra que venceu, com o arquivo de origem à direita. Repita na página da direita: a ordem se inverte. Quando um estilo seu "não pega", a resposta está sempre nesse painel — nunca no seu editor.

Quando a ordem, sozinha, não resolve

Empate de especificidade → vence quem vem por último. Mas se o seletor do framework for mais específico, a ordem não salva:

Especificidade contada como (id, classe, elemento)
SeletorPesoQuem vence
.nav-link0, 1, 0perde para o de baixo, venha na ordem que vier
.navbar .nav-link0, 2, 0vence — é o seletor do Bootstrap
.navbar .nav-link[aria-current]0, 3, 0a saída honesta: suba a especificidade
A saída não é !important — é subir a especificidade do jeito certo ou, melhor ainda, mexer nas variáveis do framework (Demo 07). No checkpoint desta aula, !important no seu CSS é erro.
