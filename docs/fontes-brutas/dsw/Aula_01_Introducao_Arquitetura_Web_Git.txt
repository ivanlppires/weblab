2. Arquitetura de uma aplicação Web

2.1 O modelo cliente-servidor
Toda a Web funciona sobre um modelo simples: um cliente (normalmente o navegador) faz requisições e um servidor devolve
respostas. Quando você digita um endereço no navegador, acontece aproximadamente isto:
1. O navegador resolve o nome do domínio para um endereço IP via DNS;
2. Abre uma conexão com o servidor (TCP, geralmente com criptografia TLS/HTTPS);
3. Envia uma requisição HTTP (ex.: GET /index.html );
4. O servidor processa e devolve uma resposta HTTP: um código de status + cabeçalhos + o conteúdo (HTML, JSON, imagem...);
5. O navegador interpreta e renderiza o HTML, baixando em seguida CSS, JavaScript, imagens e fontes referenciados na página.

2.2 O protocolo HTTP
HTTP (HyperText Transfer Protocol) é o idioma comum entre cliente e servidor. Os elementos que mais usaremos:

 Método                Uso típico

 GET                    Buscar um recurso (página, imagem, dados). Não altera nada no servidor.

 POST                   Enviar dados para criar algo (formulário de cadastro, novo registro).

 PUT / PATCH            Atualizar um recurso existente.

 DELETE                 Remover um recurso.


 Status                                                                                Significado

 200 OK                                                                                Deu certo.

 301/302                                                                               Redirecionamento.
 404 Not Found                                                                     Recurso não existe.

 500 Internal Server Error                                                         Erro no servidor.

Anatomia de uma URL:         https://www.unemat.br/cursos/tads?campus=sinop#contato    → esquema (https), domínio (www.unemat.br),
caminho (/cursos/tads), query string (?campus=sinop) e fragmento (#contato).

2.3 Front-end, back-end e banco de dados
Uma aplicação web moderna se organiza em três camadas — exatamente as três unidades da disciplina:
   Front-end (executa no navegador): HTML define a estrutura, CSS a apresentação e JavaScript o comportamento;
   Back-end (executa no servidor): recebe requisições, aplica regras de negócio, autentica usuários e monta respostas. Usaremos
   Node.js + Express;
   Banco de dados: persiste as informações. O back-end é o único que conversa com ele — o navegador nunca acessa o banco
   diretamente.

  SITE ESTÁTICO × APLICAÇÃO DINÂMICA
  Um site estático devolve sempre os mesmos arquivos prontos (Unidade 1). Uma aplicação dinâmica monta a resposta sob
  demanda, consultando dados e reagindo ao usuário (Unidades 2 e 3). Nosso projeto começa estático e ganha dinamismo camada por
  camada.

4. Git: controle de versão desde o dia 1

O projeto da disciplina será versionado com Git desde a primeira linha de código. Git registra "fotografias" (commits) do seu projeto ao
longo do tempo, permitindo voltar atrás, comparar versões e trabalhar com segurança.

4.1 Configuração inicial (uma única vez)

 git config --global user.name "Seu Nome"
 git config --global user.email "seu@email.com"



4.2 O ciclo básico

 # 1. Criar o repositório na pasta do projeto
 git init

 # 2. Ver o que mudou
 git status

 # 3. Preparar arquivos para o commit (staging)
 git add index.html        # um arquivo específico
 git add .                 # tudo que mudou

 # 4. Registrar a fotografia com uma mensagem descritiva
 git commit -m "Cria estrutura inicial do site"
  # 5. Ver o histórico
  git log --oneline


Os arquivos passam por três estados: modificado (working directory) → preparado (staging area, após git add ) → versionado
(repositório, após git commit ).

4.3 Publicando no GitHub

  # Conectar o repositório local a um repositório remoto criado no GitHub
  git remote add origin https://github.com/usuario/meu-projeto.git
  git branch -M main
  git push -u origin main

  # Nos próximos envios, basta:
  git push


   BOAS PRÁTICAS DE COMMIT
   Faça commits pequenos e frequentes, com mensagens no imperativo que expliquem o que a mudança faz: "Adiciona formulário de
   contato", "Corrige menu no celular". Evite mensagens vazias como "alterações" ou "aula".
