2. Por que usar um framework CSS?

Escrever CSS do zero para um site completo exige resolver, na mão, problemas que todo projeto tem: reset de estilos entre
navegadores, sistema de grid para organizar colunas, responsividade para celular/tablet/desktop, componentes repetitivos (menus,
botões, cards, modais) e consistência visual entre páginas. Um framework CSS entrega tudo isso pronto e testado:
   Produtividade: um menu responsivo que levaria horas sai em minutos;
   Consistência: espaçamentos, cores e tipografia seguem uma escala única;
   Responsividade por padrão: o grid se adapta aos breakpoints (larguras de tela) automaticamente;
   Comunidade: documentação extensa, exemplos e milhões de usuários.
O custo: páginas com "cara de framework" (todas parecidas), CSS não utilizado sendo baixado e a tentação de usar sem entender o CSS
por baixo. Por isso vimos HTML/CSS puro antes: framework é aceleração, não substituto do fundamento.

2.1 Duas filosofias

 Filosofia             Como funciona                                                                                  Exemplos

3. Bootstrap — o veterano dominante

Criado no Twitter em 2011, o Bootstrap (atualmente na versão 5) é o framework de componentes mais usado do mundo. Inclui grid de 12
colunas, dezenas de componentes (navbar, cards, modais, carrossel, formulários) e utilitários de espaçamento e cor — sem depender de
jQuery desde a v5.

3.1 Instalação via CDN

 <head>
   ...
   <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css"
         rel="stylesheet">
 </head>
 <body>
   ...
   <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js">
   </script>
 </body>


3.2 O grid de 12 colunas
O coração do Bootstrap: container → row → col . Cada linha tem 12 colunas virtuais; você define quantas cada bloco ocupa em cada
tamanho de tela:

 <div class="container">
   <div class="row">
     <!-- celular: 12/12 (largura total); tablet: 6/12; desktop: 4/12 -->
     <div class="col-12 col-md-6 col-lg-4">Card 1</div>
     <div class="col-12 col-md-6 col-lg-4">Card 2</div>
     <div class="col-12 col-md-12 col-lg-4">Card 3</div>
   </div>
 </div>


 Breakpoint                                          Prefixo                    Largura mínima

 Extra small (celular)                               (nenhum)                   < 576px

 Small                                                sm                        ≥ 576px

 Medium (tablet)                                      md                        ≥ 768px

 Large (notebook)                                     lg                        ≥ 992px

 Extra large                                          xl / xxl                  ≥ 1200px / ≥ 1400px


3.3 Componentes em ação: navbar + card

 <nav class="navbar navbar-expand-lg navbar-dark bg-primary">
   <div class="container">
     <a class="navbar-brand" href="index.html">Meu Projeto</a>
     <button class="navbar-toggler" data-bs-toggle="collapse"
             data-bs-target="#menu">
       <span class="navbar-toggler-icon"></span>
     </button>
     <div class="collapse navbar-collapse" id="menu">
       <ul class="navbar-nav ms-auto">
         <li class="nav-item"><a class="nav-link" href="sobre.html">Sobre</a></li>
         <li class="nav-item"><a class="nav-link" href="#contato">Contato</a></li>
       </ul>
     </div>
   </div>
 </nav>

 <div class="card" style="width: 18rem;">
   <img src="img/foto.jpg" class="card-img-top" alt="Descrição da foto">
   <div class="card-body">
     <h5 class="card-title">Título do card</h5>
     <p class="card-text">Um resumo breve do conteúdo.</p>
     <a href="#" class="btn btn-primary">Ver mais</a>
   </div>
 </div>


Repare: a navbar já vem responsiva — em telas pequenas ela colapsa no botão "hambúrguer" automaticamente.


4. Tailwind CSS — a filosofia utility-first

O Tailwind (2017) inverte a lógica: em vez de componentes prontos, oferece milhares de classes minúsculas — cada uma equivale a uma
declaração CSS. O design nasce da composição dessas classes direto no HTML. É hoje o framework que mais cresce, dominante em
projetos com React/Vue e ferramentas de IA.

4.1 Experimentando com o Play CDN (apenas para estudo)

 <head>
   ...
   <script src="https://cdn.tailwindcss.com"></script>
 </head>


  ATENÇÃO
  O Play CDN serve para aprender e prototipar. Em produção, o Tailwind é instalado via npm com um passo de build que gera somente
  o CSS realmente usado. Para o nosso projeto estático, o CDN é suficiente.


4.2 O mesmo card, em Tailwind

 <div class="max-w-sm rounded-xl shadow-lg overflow-hidden bg-white">
   <img class="w-full h-48 object-cover" src="img/foto.jpg" alt="Descrição">
   <div class="p-6">
     <h5 class="text-xl font-bold mb-2">Título do card</h5>
     <p class="text-gray-600 mb-4">Um resumo breve do conteúdo.</p>
      <a href="#" class="inline-block px-4 py-2 bg-blue-600 text-white
                         rounded hover:bg-blue-700">Ver mais</a>
    </div>
  </div>



4.3 Responsividade com prefixos
No Tailwind, a responsividade é mobile-first por prefixo: a classe vale a partir do breakpoint indicado.

  <!-- 1 coluna no celular, 2 no tablet (md), 3 no desktop (lg) -->
  <div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4">
    <div>Card 1</div>
    <div>Card 2</div>
    <div>Card 3</div>
  </div>


Prós: controle total do design, nenhum "visual padrão", CSS final mínimo. Contras: HTML verboso e curva inicial de memorização das
classes.


5. Material Design — o design system do Google

Material Design não é, a rigor, um framework: é um design system — um conjunto de princípios visuais criado pelo Google em 2014 e
usado no Android, no Gmail e em todo o ecossistema Google. Suas marcas registradas: superfícies em camadas com sombras/elevação,
cores vibrantes com paleta primária/secundária, movimento com significado e o floating action button (FAB).
Para aplicá-lo em HTML/CSS puro, usaremos o Materialize, framework de componentes que implementa o Material Design com a mesma
pegada do Bootstrap:

5.1 Instalação via CDN

  <head>
    ...
    <link rel="stylesheet"
          href="https://cdnjs.cloudflare.com/ajax/libs/materialize/1.0.0/css/materialize.min.css">
    <link href="https://fonts.googleapis.com/icon?family=Material+Icons" rel="stylesheet">
  </head>
  <body>
    ...
    <script src="https://cdnjs.cloudflare.com/ajax/libs/materialize/1.0.0/js/materialize.min.js">
    </script>
  </body>


5.2 O mesmo card, em Materialize

  <div class="row">
    <div class="col s12 m6 l4">          <!-- grid: s=small, m=medium, l=large -->
      <div class="card">
        <div class="card-image">
          <img src="img/foto.jpg" alt="Descrição da foto">
          <a class="btn-floating halfway-fab waves-effect red">
            <i class="material-icons">add</i>
          </a>
        </div>
        <div class="card-content">
          <span class="card-title">Título do card</span>
          <p>Um resumo breve do conteúdo.</p>
        </div>
        <div class="card-action">
          <a href="#">Ver mais</a>
        </div>
      </div>
    </div>
  </div>


Note as semelhanças com o Bootstrap: grid de 12 colunas ( s12 m6 l4 ), componentes por classe. A diferença está na identidade visual:
quem conhece apps do Google reconhece o estilo na hora — sombras, ondulação ao clicar (waves) e ícones Material.

  MATERIAL DESIGN ALÉM DO MATERIALIZE
  O Google mantém a especificação em m3.material.io (Material 3) e implementações oficiais como o Material Web Components.
  Em ecossistemas de componentes (React), a biblioteca MUI é a implementação mais popular. Para nosso projeto estático, o
  Materialize é o caminho mais direto.



6. Comparativo e critérios de escolha
                               Bootstrap 5                                Tailwind CSS                                Materialize (Material Design)

 Filosofia                     Componentes prontos                         Classes utilitárias                        Componentes prontos

 Curva de aprendizado          Baixa                                       Média                                      Baixa

 Velocidade p/ protótipo       Alta                                        Média                                      Alta

 Liberdade visual              Média (custom via variáveis)                Total                                      Baixa (identidade Google forte)

 Grid                          12 colunas ( col-md-6 )                     Grid/Flex utilitário ( md:grid-cols-2 )    12 colunas ( m6 )

 Ideal para                    Sistemas, painéis, sites institucionais     Produtos com design próprio, SPAs          Apps com visual estilo Google/Android

Como escolher para o seu projeto: se quer entregar rápido com visual sólido → Bootstrap; se quer identidade visual própria e não teme
HTML verboso → Tailwind; se o tema combina com a estética de aplicativo Google → Materialize. Qualquer um dos três atende o
critério "framework CSS" da Avaliação 1.

  REGRA DE OURO
  Escolha um framework por projeto. Misturar dois (ex.: Bootstrap + Materialize) gera conflitos de estilos, peso desnecessário e
  inconsistência visual.
