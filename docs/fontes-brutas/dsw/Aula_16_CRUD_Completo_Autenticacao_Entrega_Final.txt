2. A amarração final: autenticação + CRUD juntos

Nas Aulas 14 e 15 construímos as duas metades: rotas protegidas por token e o CRUD com persistência. Hoje as unimos com o toque que
falta em quase todo projeto de aula — e que diferencia os melhores: saber de quem é cada registro.

2.1 Todo registro tem dono
O middleware exigirLogin (Aula 14) já coloca os dados verificados do usuário em req.usuario . Basta usá-los ao criar:

 // controllers/produtosController.js
 exports.criar = async (req, res) => {
   const { nome, preco, categoria } = req.body;
   if (!nome || typeof preco !== "number") {
     return res.status(400).json({ erro: "nome e preco são obrigatórios" });
   }

   const produtos = await repo.lerTodos();
   const novo = {
     id: produtos.length ? Math.max(...produtos.map(p => p.id)) + 1 : 1,
     nome, preco, categoria: categoria ?? "geral",
     dono: req.usuario.email,                 // vem do TOKEN verificado — não do body!
     criadoEm: new Date().toISOString()
   };
   produtos.push(novo);
   await repo.salvarTodos(produtos);
   res.status(201).json(novo);
 };


  DETALHE DE SEGURANÇA QUE VALE NOTA
  O dono vem de req.usuario.email (extraído do token verificado pelo servidor), nunca de req.body.dono . Se viesse do body, qualquer
  cliente poderia se passar por outra pessoa — a mesma lição de sempre: nada que o cliente envia é confiável sem verificação.


2.2 Autorização: só o dono altera (401 × 403)
Autenticação responde "quem é você"; autorização responde "você pode fazer isso?". A diferença aparece nos status: 401 = não logado;
403 = logado, mas sem permissão:

 exports.atualizar = async (req, res) => {
   const produtos = await repo.lerTodos();
   const produto = produtos.find(p => p.id === Number(req.params.id));
   if (!produto) return res.status(404).json({ erro: "Produto não encontrado" });

   if (produto.dono !== req.usuario.email) {          // checagem de autorização
     return res.status(403).json({ erro: "Você não é o dono deste registro" });
   }

   const { nome, preco, categoria } = req.body;
   if (nome !== undefined) produto.nome = nome;
   if (preco !== undefined) produto.preco = preco;

    await repo.salvarTodos(produtos);
    res.json(produto);
  };

3. Roteiro de auto-teste (execute antes de entregar)

Simule a correção. Com o servidor rodando e o navegador em aba anônima:
 1. Visitante: abre o site → lista carrega (GET público) → botões de escrita ocultos → tenta POST direto via testes.http sem token → 401;
 2. Login: clica no botão do Google → nome e foto aparecem → formulário de criação visível;
 3. Create: cria um item → feedback de sucesso → item aparece na lista com seu e-mail como dono → status 201 no Network (F12);
 4. Read: busca e filtros (query string) funcionando; item inexistente → 404;
 5. Update: edita o item criado → mudança refletida sem recarregar a página;
 6. Delete: exclui com confirmação → some da lista → repetir o DELETE via testes.http → 404;
 7. Autorização: com um segundo Gmail (ou token de colega), tentar editar item alheio → 403;
 8. Persistência: derruba o servidor (Ctrl+C), sobe de novo → dados continuam lá;
 9. Validações: POST com corpo inválido → 400 com mensagem clara;
10. Higiene do repositório: node_modules/ e .env fora do Git; npm install && npm run dev funciona numa pasta limpa.

5. O que você construiu — e para onde ir agora

Em 16 encontros, o mesmo projeto atravessou toda a pilha de uma aplicação web profissional: HTTP e Git (Aula 1) → HTML semântico e
acessível (U1) → JavaScript, assincronia e SPA (U2) → API REST autenticada com persistência (U3). Esse é, literalmente, o esqueleto de
qualquer sistema web do mercado.
Caminhos naturais de evolução — bons projetos de férias e de portfólio:
   Deploy real: publicar o servidor em plataformas com camada gratuita (Render, Railway, Fly.io) e apontar um domínio — seu projeto
   sai do localhost;
   Banco de dados de verdade: trocar o repositorio.js por PostgreSQL ou MongoDB — a arquitetura em camadas que adotamos
   torna essa troca localizada;
   Frameworks de front-end: React ou Vue automatizam o padrão estado → render que você implementou à mão — a melhor ordem:
   entender o mecanismo (feito!) e só então adotar a ferramenta;
   TypeScript: tipos sobre o JavaScript que você já domina, padrão crescente no mercado;
   Portfólio: o repositório desta disciplina, com README caprichado e deploy no ar, já é peça de portfólio para estágios — trate-o como
   cartão de visita.
