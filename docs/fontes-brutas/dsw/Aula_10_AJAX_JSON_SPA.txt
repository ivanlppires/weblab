2. AJAX: a Web sem recarregar

Até o início dos anos 2000, toda interação significava recarregar a página inteira: clicar em "próxima página" de e-mails baixava todo o
HTML de novo. AJAX (Asynchronous JavaScript And XML) mudou isso: o JavaScript passou a fazer requisições HTTP por conta própria, em
segundo plano, e atualizar só o pedaço necessário do DOM.
É o que o Gmail faz ao chegar um e-mail novo, o que uma rede social faz no rolar infinito, o que qualquer busca com sugestões faz a cada
tecla. Ironia histórica: o "X" era de XML, mas o formato que venceu foi o JSON — o nome AJAX ficou. A ferramenta original era o
 XMLHttpRequest ; hoje o padrão é a Fetch API, que usaremos.



3. JSON: o idioma dos dados na Web

JSON (JavaScript Object Notation) é texto com a sintaxe de objetos JS — legível por humanos e por qualquer linguagem (Python, Java,
PHP... todas falam JSON). É o formato do tráfego navegador ↔ servidor:

 {
     "nome": "Camiseta",
     "preco": 49.9,
     "disponivel": true,
     "tamanhos": ["P", "M", "G"],
     "fornecedor": { "cidade": "Sinop", "uf": "MT" }
 }


Diferenças em relação ao objeto JS: chaves sempre entre aspas duplas, sem funções, sem comentários, sem vírgula sobrando no final.
Conversões:

 const texto = JSON.stringify(produto);      // objeto → texto JSON (para ENVIAR)
 const obj = JSON.parse(texto);              // texto JSON → objeto (ao RECEBER)




4. Fetch: requisições HTTP com JavaScript

4.1 GET: buscando dados
Usaremos APIs públicas de teste — a JSONPlaceholder (jsonplaceholder.typicode.com) simula posts e usuários, e o ViaCEP
(viacep.com.br) consulta CEPs brasileiros de verdade:

 async function buscarPosts() {
   const resposta = await fetch("https://jsonplaceholder.typicode.com/posts");

     if (!resposta.ok) {                          // status fora de 200-299
       throw new Error(`Erro HTTP ${resposta.status}`);
     }

     const posts = await resposta.json();          // parse do corpo (também é assíncrono!)
     return posts;                                        // array de objetos, pronto para map/filter
 }


  PEGADINHA ESSENCIAL DO FETCH
  O fetch só rejeita a Promise em falha de rede (sem internet, DNS). Um 404 ou 500 resolve normalmente — por isso o teste if
  (!resposta.ok) é obrigatório. Sem ele, seu código tentará processar uma página de erro como se fossem dados. E note os dois
  awaits: um para os cabeçalhos chegarem, outro para o corpo ( .json() ).


4.2 Exemplo real: preenchendo endereço pelo CEP

 const campoCep = document.querySelector("#cep");

 campoCep.addEventListener("change", async () => {
   const cep = campoCep.value.replace(/\D/g, "");              // só dígitos
   if (cep.length !== 8) return;

     try {
       const resp = await fetch(`https://viacep.com.br/ws/${cep}/json/`);
       if (!resp.ok) throw new Error("Falha na consulta");
       const dados = await resp.json();
       if (dados.erro) throw new Error("CEP não encontrado");

     document.querySelector("#rua").value = dados.logradouro;
     document.querySelector("#cidade").value = `${dados.localidade}/${dados.uf}`;
   } catch (e) {
     document.querySelector("#erro-cep").textContent = e.message;
   }
 });


4.3 POST: enviando dados
O formulário com preventDefault (Aula 7) agora envia de verdade — sem recarregar a página:

 form.addEventListener("submit", async (e) => {
   e.preventDefault();

     const novoPost = {
       title: form.titulo.value,
       body: form.mensagem.value,
       userId: 1
     };

     try {
       const resp = await fetch("https://jsonplaceholder.typicode.com/posts", {
         method: "POST",
         headers: { "Content-Type": "application/json" },   // "estou enviando JSON"
         body: JSON.stringify(novoPost)                     // objeto → texto
       });
       if (!resp.ok) throw new Error(`Erro HTTP ${resp.status}`);

     const criado = await resp.json();                    // o servidor devolve o recurso com id
     exibirMensagem(`Enviado com sucesso! ID: ${criado.id}`);
     form.reset();
   } catch (erro) {
     exibirMensagem("Não foi possível enviar. Tente novamente.");
   }
 });


Na Unidade 3, o endereço jsonplaceholder... será substituído pela sua própria API Express — o código do front-end permanecerá
praticamente idêntico.


5. SPA: Single Page Application

Juntando as peças, chegamos ao padrão que define as aplicações modernas: a SPA carrega um único HTML; a partir daí, o JavaScript
intercepta a navegação, busca dados via AJAX e troca o conteúdo do DOM — a página nunca recarrega.

                         Site multipágina (MPA)                                             SPA

 Navegação               Cada clique = novo HTML do servidor                                JS troca o conteúdo; sem recarga

 Dados                   Embutidos no HTML                                                  Buscados via AJAX (JSON)

 Sensação                "Site"                                                             "Aplicativo"

 Exemplos                Blogs, portais, institucionais                                     Gmail, WhatsApp Web, painéis


5.1 Mini-roteador: navegação por seções
Frameworks como React e Vue automatizam SPAs; o mecanismo essencial, porém, cabe em poucas linhas — e é o que a Avaliação 2
espera:

  <!-- HTML: seções-"tela", só uma visível por vez -->
  <nav>
    <a href="#inicio">Início</a>
    <a href="#catalogo">Catálogo</a>
    <a href="#contato">Contato</a>
  </nav>
  <main>
    <section id="inicio" class="tela">...</section>
    <section id="catalogo" class="tela oculta">...</section>
    <section id="contato" class="tela oculta">...</section>
  </main>

  // JS: o "roteador" — reage à mudança do hash (#) na URL
  function navegar() {
    const rota = location.hash || "#inicio";

      document.querySelectorAll(".tela").forEach(t => t.classList.add("oculta"));
      document.querySelector(rota)?.classList.remove("oculta");

      if (rota === "#catalogo") carregarCards();         // busca dados ao entrar na tela
  }

  window.addEventListener("hashchange", navegar);         // usuário navegou
  navegar();                                              // primeira carga (respeita a URL atual)


Usar o hash mantém o histórico do navegador funcionando: voltar/avançar e favoritar continuam operando — cuidado clássico de SPAs
bem feitas.
